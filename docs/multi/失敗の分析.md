## 2. 未解明点の確認

- C1 stag #6: r1 は南通路の経由地に (3.03, 1.39) で到着した後、北壁際で 24 秒進まず、「通路を特定できない」停止 → 再試行 → Nav2 失敗(67 秒)。r2 は中央通路を通って 44.9 秒で到着。台間距離 1.04 m 以上。原因は Nav2 の走行(壁際の停滞)。
- dest で失敗が出なかった理由: 先に着いた台と後から着いた台が、出荷口 (6.2, 0.8) の周りに約 0.34 m 離れて並んで止まった(例 C0 dest #1: r2 (6.26, 1.04)、r1 (5.97, 0.86)、どちらも目標から約 0.25 m)。目標の許容範囲内に 2 台が並べたため、目的地の占有は起きなかった。
- C2 再確認 #3 の 54.1 秒: r2 は 27.8 秒で到着。r1 は南通路の西の入口 (2.0, 1.33) で約 16 秒(20〜36 秒)止まり、少し後退してから東向き車線を通った。通行止めの報告はなく、Nav2 の回復動作で抜けた。r2 が通った後の停滞で、原因(コストマップに残った相手の跡か、壁際か)は特定できない。
- dead の C1 が中央通路を選んだ理由: C1 の LLM には走行する台(r1)の情報だけを渡しており、停止した r2 は入力に含まれない。理由文は「他のロボットがまだ決定していないため、中央通路を使用」。停止台を判断したものではなく、1 台だけの割り当てで最短でない通路を選んだ。
- dest の C1 が検証を通らなかった理由: r2(充電 → 出荷口)は通路を通らないが、出力形式は台ごとに通路を 1 つ必ず選ばせ、検証は「選んだ通路を実際に通るか」を確かめる。通路を通らない台には正しい答えがなく、30 回すべて差し戻された。出力形式の設計の不備(1 台版の 7-4・7-5 と同じ種類の問題)。
