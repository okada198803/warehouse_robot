測定 2026-10-15〜16。ブランチ `multi-robot`。単体構成の検証データ・コードは変更していない(タグ `freeze-2026-10-13`、`docs/auto/SHA256_freeze-2026-10-13.txt`)。
設計と事前の予想は `設計.md`、集計は `summary.md`(opp)・`summary_<シナリオ>.md`・`summary_all.md`、失敗の分析は `失敗の分析.md`、生データは `<条件>[_<シナリオ>].csv`。再現は `host/run_multi_auto.sh`(使い方は `../検証ランナー_使い方.md` の 6 章)。

## 条件
| 条件 | 内容 |
|---|---|
| C0 | 協調なし(各ロボットが 1 台版と同じ仕組みで動く。相手は LiDAR の障害物) |
| C1 | 統制 LLM(qwen2.5:7b)が走行する台の現在地・目的地・通路ごとの距離を見て、台ごとに通る通路を割り当てる。検証し、NG なら差し戻し(最大 2 回)、通らなければ C0 |
| C1a | C1 の第 1 版(避ける通路を出力)。opp のみ |
| C2w / C2 | 南通路を幅 1.5 m にしたワールド。C2 は車線の規則(左側通行)を加える。cross・crossj・dest は対象外 |
| C3 | ロボット間通信。使う通路・向きを `/fleet/intent` に出発前に 1 回(0.4 秒間隔で 4 回)送り、id の優先順位の低い側が競合する通路を避ける。受信側は最大 3 秒待つ |
| C3d / C3h / C3x | C3 で、送信を 2 秒遅延 / 送信ごとに 50% 不達 / 全不達(opp) |
| C4 | 2 層: C3 に加え、応答のない台・未解決の競合があるときだけ C1 を呼ぶ。応答のない停止台の通路は LLM に伝え、その通路の割り当ては差し戻す(opp・same・dead) |
| C4x | C4 で全不達(opp) |
| N0 | Nav2 のみ。Planner・plan_executor・通行止めの記憶・LiDAR の通路確認を使わず、目的地を Nav2 に直接送る(opp・dead) |

## シナリオ
opp(正面すれ違い)、same(同方向・追従)、cross(交差・別の目的地)、wait(通路内で 25 秒待機中の台)、stag(r2 が 6 秒遅れて出発)、dest(同じ目的地)、dead(南通路内で停止したままの台)、ばらつき版 oppj・samej・crossj・waitj(位置 ±0.15 m、向き ±0.3 rad、出発遅れ 0〜5 秒、試行番号で固定)。各 10 試行、上限 150 秒。

## 観察
1. 差が出たのは逆向きの取り合い(opp・oppj)。C0 12/20 に対し C1・C2 20/20(p=0.003)、C3 19/20(p=0.020)。他のシナリオは C0 でも 8〜10/10。
2. C1 と C3 の到着率の差は判定できない。C3 は協調 0.1 秒で、衝突のない場面は C0 と同じ時間。C1 は毎回 LLM を呼び、迂回の割り当ても出るため約 12 秒遅い。
3. 通信の成否が結果を決めた。2 秒遅延は影響なし、50% 不達 7/10、全不達 6/10(C0 と同じ)。
4. 2 層(C4)は、通常は C3 と同じ時間で、全不達・停止台のときだけ統制 LLM が補い 10/10。
5. dead の C1 の 10/10 は偶然。LLM の入力に停止台は含まれず、1 台だけの割り当てで最短でない中央通路を選んだ。
6. dest の C1 は検証を通る出力が 0/30(通路を通らない台にも通路を選ばせる出力形式の不備)で、全試行 C0 の動作。dest で失敗が出なかったのは、2 台が出荷口の許容範囲(約 0.25 m)に並べたため。
7. 単一で効いた規則の副作用: 停止原因の分類(通路を特定できない停止は登録しない)が停止・待機中の相手も登録せず 6 件失敗。到着後に目的地で待つ台が相手の出口を塞ぎ 12 件失敗。最短性の検証は全台を南通路に集めた。
8. AI 層あり(C0)と Nav2 のみ(N0): dead 8/10・28.2 秒 対 8/10・50.2 秒、opp 6/10 対 4/10。

## 結果を見た後の変更
- C1 の出力形式を変更(C1a → C1)。
- 名前空間の扱いを変更し、C3・C2・C0 を各 3 回再確認(`*_recheck.csv`)。
- シナリオの追加(same 以降)、追加試験(C3d・C3h・C3x・C4・C4x・N0)は、それぞれ前の結果を見てから追加した。
- 実行の自動化に時間切れ処理と段階ごとの再起動を追加(止まった試行は記録せず再実行)。

## 限界
各 10 試行で 10/10 と 9/10 は区別できない。固定配置は同一初期条件の繰り返し。C1 は温度 0 で割り当てが毎回同じ。C3 の優先順位は id の固定規則。C2 は環境の改変が前提。追加試験は opp(一部 dead・same)のみ。N0 の dead の障害物は停止した台。接触は検出していない(0.22 m 以下を「接触の可能性」とした)。3 台以上は未検証。シミュレータ上の結果。
