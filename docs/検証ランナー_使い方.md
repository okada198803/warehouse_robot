# 検証ランナーの使い方(V1〜V8)

実行場所は Mac のターミナル(【host】)。Docker Desktop と Ollama を起動しておく。
作業フォルダ: `~/Desktop/pai_final/host`。仮想環境は `run_*.sh` が有効にする。

## 1. 初回(試運転)

1. 【host】`cd ~/Desktop/pai_final/host && source .venv/bin/activate && python -m pytest tests -q`(35 件通ること)
2. 【host】`./run_llm_suites.sh 1 1`(各 1 回。ROS 不要。動作確認のみ。経験を作り直す)
3. 【host】`N_V3=1 N_V5=1 ./run_auto.sh`(Gazebo を自動起動して各 1 回。V7 も実行)
4. 動かなければ、`docs/auto/logs/run_auto.log` と、コンテナ内 `/tmp/nav.log`(`docker compose -f ../docker/compose.yaml exec ros tail -50 /tmp/nav.log`)を Claude に渡す。
5. 試運転の結果は消す: `rm -f ../docs/auto/*.csv ../docs/計測_LLM_V1_*.csv ../docs/計測_LLM_V4.csv`

## 2. 本番(無人)

```
cd ~/Desktop/pai_final/host
./run_llm_suites.sh            # V1 + V4(約 1〜1.5 h)
./run_auto.sh                  # V2 → V3 → V5 → V7 → V8(約 5 h)
```
- 途中で止まっても同じコマンドで再実行すれば、完了済みの試行を飛ばして続きから実行する。
- 実行中は Mac をスリープさせない(`caffeinate` を内部で使う)。ふたを閉じない。電源をつなぐ。
- 画面の noVNC で手動起動した launch は、先に閉じる(スクリプトが止めて起動し直す)。
- 異常が続くとシミュレータを自動で再起動する(1 つの検証につき最大 6 回)。
- 集計だけ見る: `python summarize_auto.py`(`docs/auto/summary.md`)

## 3. 仕様(結果の読み方)

- 試行ごとにロボットを初期位置(0.8, 0.8)へ移動し、パレットを全て撤去し、コストマップを消去する。初期位置に戻らなければ再起動する。
- 通行止めの申告は規則で登録される(LLM を使わない)。V3 の D・E は「南通路は塞がれている」の後に「南通路は片付いた。出荷口へ行って」と指示する。
  - D: パレットが残っている(口頭の解除が誤り)。事前確認 ON は走行前に検知、OFF は南通路で立ち往生して検知。
  - E: パレットを置かない(口頭の解除が正しい)。事前確認が正しい解除を棄却しないことを確認する。
- `t_first_blocked` は、計画の送信から blocked の報告までの時間。事前確認 ON の場合は後退の時間を含む。
- V5 は経験(experience.json)を使わない。条件は A+検証のみ。
- 経過ログ(odom の軌跡を含む)は `docs/auto/logs/<検証>_<条件>_<回>.jsonl`。軌跡図に使える。

## 4. 手動(V5b / V5c)

V5b: RViz の局所コストマップ
1. 【host】`./run_auto.sh` の実行が終わっていることを確認する。
2. 【noVNC】`bash ~/ros2_ws/run_nav.sh`(RViz 付きで起動)
3. 【docker】`ros2 run ai_nav obstacle place south_aisle`
4. 【host】`python llm_commander.py` で「出荷口へ行って」。停止した時点で RViz の局所コストマップ(Local Costmap)と LiDAR 点群のスクリーンショットを撮る。
5. 中央通路が障害物として描かれていないか見る。

V5c: `/cmd_vel` の発行元
1. 【docker】`ros2 topic info /cmd_vel --verbose`(ロボット走行中と、`llm_commander.py` 起動前/後の両方)
2. `rosbridge_websocket` が現れる条件を調べる。仮説: `ros_link.py` が `/cmd_vel` を advertise するため、接続中は rosbridge が発行元として表示される(実際に速度を出しているとは限らない)。

## 5. 制限

- 自動ランナーは試走前の状態で書いた。試運転で修正が必要になる可能性がある。
- 実走は Gazebo の物理に依存するため、結果は試行ごとにばらつく。回数(n=10/20)は統計的な有意性を示すものではなく、傾向の確認用。
- 事前確認 OFF は `ros2 param set /plan_executor precheck false` で切り替える。ランナーが各試行の前に設定し直す。

## V8(到着時間の予測)と V7(しきい値の自動選択)の読み方

- V8: `analyze_eta.py` が、実測から `eta_model.json`(1 m あたりの秒・停止 1 回あたりの秒・定数)を当てはめる。精度は、**経路ごとに除いて当てはめ直した場合**の誤差で見る(当てはめに使っていない経路での予測)。`llm_commander.py` は、`eta_model.json` があれば使い、送信時に「到着予測」、完了時に「予測・実測・誤差」を表示する。再計画後は、残り経路の予測に置き換わる。
- V7: 点数の分布から、検知漏れ・誤検知が最小で、分離の幅の中央になるしきい値を選ぶ。位置ごとに除いて選び直した場合の誤りも併記する。選ばれた値を本番に反映する場合は、`plan_executor` の `scan_min_hits` の既定値と、`auto_sim.py` の `set_param('scan_min_hits', ...)` を揃え、V3 以降を再測定する。

## 荷物の箱と測定条件

V2〜V7 の測定は、荷物搬送を追加する前の世界(箱なし)で行った。ワールドに荷物の箱を追加した後の V8 の初回(箱が見える状態)では、中央通路を含む経路が全試行で停止した(`docs/auto/v8_boxes_visible/`)。そのため、`auto_sim.py` は各試行の初期化で箱を床下へ隠し、追加前と同じ条件にそろえる(`AUTO_CARGO=visible` で隠さない)。
