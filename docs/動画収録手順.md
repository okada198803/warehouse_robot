# 動画の収録手順(場面ごとの操作と、実行するコマンド)

構成は Project の `claude/動画構成案.md`(目安 2:52)。録画は Mac の画面収録(手動)で行う。
**ロボットの操作の扱い:** 場面 2〜6 は、人の入力(指示の文、指差し、ジェスチャー)そのものを見せる場面なので手動で行う。場面 4 のパレット配置と、テイク間のリセットはスクリプトで自動化した。場面 7(2 台)は自動実行の様子を録画する。

## 0. 端末の用意(録画の前に 1 回)

端末は Mac のターミナル 3 つ(T1・T2・T3)と、ブラウザの noVNC(http://localhost:6080)内のターミナル 2 つ(N1・N2)。

| 名前 | 場所 | 用途 |
|---|---|---|
| 【N1】 | noVNC のデスクトップのターミナル 1 | シミュレータと Nav2 の起動 |
| 【N2】 | 同 ターミナル 2 | Gazebo の画面(`ign gazebo -g`)。録画では左半分に置く |
| 【T1 指示】 | Mac のターミナル | `llm_commander.py`(指示の入力とログ)。録画では右半分に置く |
| 【T2 操作】 | Mac のターミナル | リセット、パレット配置、docker の操作 |
| 【T3 カメラ】 | Mac のターミナル | `pointing_cam.py`(指差し)・`gesture_teleop.py`(ジェスチャー) |

**T1・T2・T3 のそれぞれで、最初に 1 回実行する**(仮想環境の有効化、プロンプトの短縮でユーザー名・ホスト名を映さない、画面消去):

```bash
cd ~/Desktop/pai_final/host && source .venv/bin/activate && PS1='$ ' && unset COMPOSE_FILE && clear
```

**T2 で 1 回だけ**(スクリプトに実行権限を付ける):

```bash
chmod +x ~/Desktop/pai_final/host/video_reset.sh ~/Desktop/pai_final/host/run_multi_auto.sh
```

- 文字は大きく(Mac ターミナルで `Cmd + プラス` を 3〜4 回)。
- 録画は `Cmd + Shift + 5` →「選択部分を収録」。タイトルバー(ユーザー名が出ることがある)を範囲から外す。

## 1. 事前準備(最初の 1 回)

以降、「T2:」のように端末名を先頭に書く。コードブロック内は 1 行ずつ実行する。

### 1-1 Docker Desktop と Ollama を起動する(Mac)

```bash
open -a Docker
open -a Ollama
```

起動したら **T2** で確認する(どちらもエラーなく結果が出ること):

```bash
docker info > /dev/null && echo "docker OK"
ollama list | grep qwen2.5:7b
curl -s http://localhost:11434/api/tags > /dev/null && echo "ollama OK"
```

`Ollama` アプリがない場合は `ollama serve &` を実行する。

### 1-2 単一用コンテナを起動し、複数台用を止める(T2)

```bash
cd ~/Desktop/pai_final/docker
docker compose -f compose.multi.yaml stop
docker compose -f compose.yaml up -d
docker ps --format '{{.Names}}\t{{.Status}}'
cd ~/Desktop/pai_final/host
```

確認: `pai-ros` が `Up`。`pai-ros-multi` が表示されない(または Exited)。

### 1-3 Nav2 つきシミュレータを起動する(N1)

ブラウザで http://localhost:6080 を開き、デスクトップの端末を 1 つ開いて(N1):

```bash
bash ~/ros2_ws/stop_nav.sh
bash ~/ros2_ws/run_nav.sh cargo:=true
```

ログが流れ続ける(終了しない)。1〜2 分待つ。**T2** で起動の完了を確認する:

```bash
../docker/ros_exec.sh ros2 lifecycle get /bt_navigator
```

確認: `active [3]` と出る。出なければ数十秒待って再実行。

### 1-4 Gazebo の画面を開く(N2)

noVNC のデスクトップで 2 つ目の端末を開き(N2):

```bash
ign gazebo -g
```

確認: 倉庫、ロボット(入荷口)、荷物の箱 3 つ(北・中央・南)が見える。ウィンドウを画面の左半分に置く。

**カメラをロボットに寄せる(動画で判別できる大きさにする。T2):**

```bash
./video_camera.sh top          # 真上から全景(高さ 2.8。実機で全景とロボットの判別を確認済み)。調整: ./video_camera.sh top 3.5
./video_camera.sh follow       # ロボットを追従(後方 1.6 m・上 1.8 m)。調整: ./video_camera.sh follow 1.2 1.4
./video_camera.sh free         # 追従を解除
```

使い分け: 場面 2・3・5(通路全体の動き)は `top`、場面 4(パレットに近づく様子)は `follow` が見やすい。場面ごとに録画前に切り替える。`video_reset.sh` はカメラを変えない。Gazebo を開き直すと既定に戻るので、そのつど再実行する。

### 1-5 LLM のウォームアップ(T1。録画に初回の遅れを入れないため)

```bash
python llm_commander.py
```

プロンプト `>` が出たら次を入力し、ロボットが出荷口に着くまで待つ:

```
出荷口へ行って
```

到着後、`Ctrl+C` で終了する。

### 1-6 初期状態に戻す(T2)

```bash
./video_reset.sh
```

確認: `リセット完了` と出て、ロボットが入荷口に戻り、箱が初期位置にある(N2 の画面)。

### 1-7 指差しの校正(T3。カメラの位置を変えたら毎回)

```bash
python pointing_cam.py
```

起動時に `校正値: {...}` が出る。黒い画面に手の骨格だけが映る。**小窓を選択した状態で**次のキーを押す(ターミナルではなく小窓にフォーカスする):

| 順 | 手の動き | キー |
|---|---|---|
| 1 | 北の荷物の方向を指し続ける | `n`(押してから 2 秒間の中央値を採る。`校正: cargo_north = …` と出る) |
| 2 | 中央の荷物の方向を指し続ける | `c`(`校正: cargo_center = …`) |
| 3 | 南の荷物の方向を指し続ける | `s`(`校正: cargo_south = …`) |
| 4 | | `w`(`保存: …/pointing_calib.json`) |

確認: もう一度、北・中央・南をそれぞれ 1 秒指すと小窓に `SELECTED`、T3 に `指差し確定` が出る。確認後 `q` で終了。初期値に戻すときは `r`。

## 2. テイク間のリセット(各場面の前に毎回)

**T1:** コマンダーを止める(通行止めの記憶が消える)。

```
Ctrl+C
```

**T2:** パレット撤去、箱を初期位置へ、ロボットを入荷口へ、コストマップ消去。

```bash
./video_reset.sh
```

場面 5 だけは、南通路にパレットを置いた状態にする:

```bash
./video_reset.sh south
```

うまく戻らない場合は **N1** で `Ctrl+C` のあと次を実行し、**N2** の `ign gazebo -g` も開き直す(1〜2 分):

```bash
bash ~/ros2_ws/stop_nav.sh
bash ~/ros2_ws/run_nav.sh cargo:=true
```
