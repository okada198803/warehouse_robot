### 計測 A・B(`docs/計測_LLM_{base,A,AB,train}.csv`)

条件: qwen2.5:7b、温度 0、10 シナリオ × 5 回(ROS なし)。`base` は最短性の検証なし・経験なし(旧仕様の再計測)、`A` は最短性の検証あり、`AB` は A に加えて経験を参照(読み取り専用)。経験は `--train` の 6 シナリオ(充電ステーション・東ホール)から作り、計測用(出荷口・事務所前)とは目的地を分けた。通行止めの状況(南封鎖・南中央封鎖・中央封鎖・なし)は学習と計測で共通。

| 指標 | base | A | A + B |
|---|---|---|---|
| 検証通過率(最終) | 55/80 = 69% | 55/85 = 65% | 55/70 = 79% |
| 初回案の通過率(S5 を除く) | 30/40 = 75% | 30/40 = 75% | 40/40 = 100% |

| S3 南封鎖: LLM 呼び出し / 応答時間 | 2 回 / 約 9.1 秒 | 3 回 / 約 13.9 秒 | 1 回 / 約 5.0 秒 |

| 再計画の初回通過率 | 15/15 | 15/15 | 15/15 |

### 結果の読み方
- base では、S3(南封鎖)で 5/5 とも北通路(約 10.3 m)を選んだ。通行止めは避けているため正答と判定されていたが、中央通路(約 7.5 m)より約 37% 長かった。A でこれを検知して差し戻し、5/5 が最短の中央通路になった(最短率 91% → 100%)。
- A の代償として、S3 の LLM 呼び出しが 2 回 → 3 回になり、応答時間が約 9.1 秒 → 約 13.9 秒に増えた。
- B(経験の参照)で、S3・S4 の初回案が 10/10 検証を通り、LLM 呼び出しは 1 回になった。応答時間は S3 で約 13.9 秒 → 約 5.0 秒(A 比)。差し戻しの回数が減ったため。
- 経験の参照は、通行止めなしの S1・S2・S7・S8 でも行われた(封鎖なしの経験 1 件を参照)。結果は変わらず、応答時間は約 0.3〜0.5 秒増えた。

### 計測の制約(報告書に記載する)
- 計測の盤面(通行止めの組合せ)は学習時と共通で、目的地だけが異なる。初見の盤面への汎化は検証していない。
- 経験は 6 件。学習データは自システムの出力で、最短かつ検証を通ったものだけを保存している。
- 温度 0 のため、5 回の繰り返しは独立した試行ではない。
- 学習(重みの更新)は行っていない。「経験の再利用による文脈内の改善」であり、モデルの再学習とは区別する。
- 学習時、T3(南中央封鎖・充電)と T6(中央封鎖・充電)は初回 NG で、差し戻しで正答に至った。T2・T4 は先に保存された経験を参照して初回で通過した。

### D・E の実機確認(シミュレータ、2026-10-11)

**事前確認**: `check_aisle_scan.py` で受入エリアから LiDAR の帯の点数を確認。南通路 16 点、他の通路 0 点(パレットは南通路中央に配置)。

**D: 口頭解除した通路の事前確認**(手順: 南通路にパレットを置く → 「南通路が塞がっている」→「南通路は片付いた」→「出荷口へ行って」。パレットは残したまま)

| 条件 | 回数 | 送信から blocked 報告まで | cause | scan_hits |
|---|---|---|---|---|
| 事前確認あり(`precheck=true`) | 3 | 約 1 秒 | obstacle | 16 |
| 事前確認なし(`precheck=false`) | 2 | 59 秒、46 秒(平均約 52 秒) | obstacle | 109〜124(パレット接近後) |

- 事前確認ありでは、走行前に残存パレットを検知し、中央通路へ再計画して到着した。
- 事前確認なしでは、南通路へ進入してパレット近傍で停止検知(stuck)になるまで待つ。2-8c の約 80 秒より短いが、同程度の遅れが出る。
- 制約: 事前確認あり n=3、なし n=2。時刻のログ分解能は 1 秒。

**E: 停止原因の分類**(`scan_min_hits=999` で LiDAR の判定を無効にし、パレットあり南通路を通る「出荷口へ行って」を送信)

- 制約: `unconfirmed` は閾値の操作で作った状況。自然発生した誤検知は観察していない。

**D の途中で見つかった不具合と修正**
- 現象: 「南通路が塞がっている」を LLM が通行止めの登録(`blocked_add`)なしの goto として解釈し、`blocked` が空のまま「最短でない」と差し戻し、西ホール経由になった。
- 修正: 「塞が」「通れない」等の語を含む発話は、ルールで通行止めに登録する(`_block_targets`、`_block_only`)。テスト 3 件を追加(host 30 件)。再実行で正常に動作した。
- `ros2 param set scan_min_hits / precheck` が初期化時の 1 回しか読まれず反映されなかった。使用時に `get_parameter` で読むよう修正。

**fix 3(未特定停止の再試行)の実機確認**: 受入エリア付近で `near_aisle=None` の停止(位置 (0.27, 1.46))が発生。登録せず 1 回再試行して到達した。

**前提と制約**
- map と odom は同一座標(恒等変換)。LiDAR の取り付け位置のずれは無視。しきい値(3 点・帯幅 0.3 m)は設計値。
- 事前確認は、ロボットの位置から通路が見える場合に限る(受入エリアからは南通路が見える。中央通路は接近後)。
- `precheck` パラメータで D を無効化できる。実験後は `ros2 param set /plan_executor scan_min_hits 3` で戻す。
