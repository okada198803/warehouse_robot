# 荷物搬送(指差し + 言葉)の手順

「あれを出荷口へ運んで」と言いながら荷物を指すと、ロボットが荷物置き場へ向かい、積載(模擬)し、出荷口へ運ぶ。
把持・積載の物理は対象外。荷物置き場への到着を積載、計画の最後への到着を荷降ろしとみなし、
Gazebo の箱(見た目のみ・衝突なし)をロボットの上へ移して、目的地の前に降ろす。

## 構成

| 要素 | 内容 |
|---|---|
| コントロールルーム | 倉庫の西壁の外(x < 0)にある見た目だけの部屋。操作者の位置は (−0.8, 2.5)、東向き。Mac のカメラの位置に相当 |
| 荷物置き場 | 北 `cargo_north` (1.1, 3.4) / 中央 `cargo_center` (1.0, 2.5) / 南 `cargo_south` (1.1, 1.6)。箱は西壁寄りの x=0.5(到着地点の 0.5〜0.6 m 先)。ホール車線(x=1.6〜1.7)には置かない |
| 見え方 | 操作者(東向き)から見て、北が左、南が右 |
| 指差し | `host/pointing_cam.py`。人差し指だけを伸ばした向きを、校正した 3 方向のうち最も近いものに対応づける。同じ方向を 1 秒保持で確定 |
| 解決 | `llm_commander.py --cargo`。「あれ・それ・これ」を指差しで確定した荷物に置き換える。指差しがなければ聞き返す |
| 実行 | `plan_executor`(荷物地点で 2 秒待つ)+ `cargo_sim`(箱の移動) |

- 箱・コントロールルームは衝突を持たず、地図・Nav2 の静的地図には載らない(地図は生成前後でバイト一致を確認済み)。
- **ただし、LiDAR(gpu_lidar)は見た目の形状も検出する**ため、箱は走行中の障害物(コストマップ)として働く。箱を中央通路の入口前のホール車線(x=1.6〜1.7)に置いた初期の配置では、中央通路を通る経路で停止し(V8 の初回は 17/30 が成功)、この原因だった。箱を x=0.5 に移して解消した(2026-10-13)。以前の「箱は障害物にならない」という記載は誤りだった。
- 通路の事前確認の帯(x ≥ 2.3)には箱が入らない(`test_boxes_stay_out_of_aisle_scan_bands`)。
- 荷物の計画は、経験(experience.json)に保存しない。

## 初回(Docker 側。entry point を追加したため再ビルドが必要)

1. 【noVNC】`cd ~/ros2_ws && colcon build --symlink-install && source install/setup.bash`
2. 【noVNC】ワールドを再生成した場合のみ: `python3 ~/ros2_ws/src/ai_nav/tools/gen_warehouse.py`(地図は変わらない)

## 実行

1. 【noVNC】`bash ~/ros2_ws/run_nav.sh cargo:=true`(既定は hide: 積載で箱が消え、荷降ろしで目的地の前に現れる。`cargo_mode:=follow` は箱がロボットに載る方式で、実機では箱が表示されなかったため実験的)
2. 【Gazebo GUI】別ターミナルで `ign gazebo -g`。箱が 3 つ、西の壁の外にコントロールルームが見える
3. 【host】`cd ~/Desktop/pai_final/host && source .venv/bin/activate`
4. 【host・ターミナル 1】`python pointing_cam.py`(初回は校正)
5. 【host・ターミナル 2】`python llm_commander.py --cargo`
6. 手を荷物へ向けて 1 秒保持 → `SELECTED: ...` と出たら、ターミナル 2 に「あれを出荷口へ運んで」と入力する

## 校正(初回と、カメラ位置を変えたとき)

1. `pointing_cam.py` のウィンドウを選択する(カメラ映像に手の骨格が重なって出る。`--skeleton-only` なら黒背景に骨格だけ)
2. 北の荷物を指して `n` を押す → 2 秒間そのまま保持。同様に `c`(中央)、`s`(南)
3. `w` で保存する(`host/pointing_calib.json`。Git の管理外)
4. 画面下の定規で、3 方向の目盛りと現在の指差し(橙の点)が対応することを確認する
- 校正前の初期値は、鏡像で左(北)= −1.0、中央 = 0、右(南)= +1.0。

## 確認項目

| # | 確認 | 方法 | うまくいかない場合 |
|---|---|---|---|
| 1 | ワールドが起動し、箱とコントロールルームが見える | Gazebo GUI | `gen_warehouse.py` を再実行し、`ign model --list` で `cargo_*` を確認 |
| 2 | 箱を動かせる | 【docker】`ign service -s /world/warehouse/set_pose --reqtype ignition.msgs.Pose --reptype ignition.msgs.Boolean --timeout 500 --req 'name: "cargo_center" position {x: 1.6 y: 3.5 z: 0.5}'` で箱が動く | `cargo:=true cargo_mode:=hide` も同じ仕組み。動かない場合はモデルを remove/create 方式に変更する |
| 3 | 積載で箱が消え、荷降ろしで現れる(hide)【確認済み】 | 「南の荷物を出荷口へ運んで」(指差し不要) | follow は未解決(箱が表示されない)。`cargo_sim` のログで set_pose の結果を確認できる |
| 4 | (follow のみ)箱の高さ | ロボット上面に載るか | `cargo_sim` の `carry_z`(既定 0.22 m)を調整 |
| 5 | 荷降ろし【確認済み】 | 出荷口の手前に箱が降りる | 位置は `cargo_logic.DROP_AHEAD` |
| 6 | 指差し【確認済み】 | `pointing_cam.py` で 3 方向が安定して確定する。「あれ」を先に入力して聞き返された場合も、指差しの確定で続行する | 校正をやり直す。`--dwell` を長くする |
| 7 | パレットで迂回しながら搬送【確認済み】 | 荷物を積んだ後、南通路にパレットを置く | 再計画は積載中でも動く(状況に「積載中」を渡す) |

## 試験用コマンド

- 箱を初期位置へ戻す: `ros2 topic pub --once /ai/cargo_cmd std_msgs/msg/String "{data: reset}"`
- 指差しなしの動作確認: `python llm_commander.py --cargo` で「南の荷物を出荷口へ運んで」
- ROS なしの判断確認: `python llm_commander.py --cargo --dry-run`
- 聞き返し: 指差しなしで「あれを出荷口へ」と入力する → 「どの荷物ですか?」

## 設計上の注意

- 中央・北の荷物から出荷口へは、静的地図上の最短で中央通路を通る(南の荷物は南通路)。
- 通行止めの検証は、区間ごと(現在地 → 荷物 → 目的地)に行う。最短性の差し戻しは、荷物を含む計画では行わない。
- 積載中に停止・通行止め・再計画になっても、箱はロボットに載ったまま。次に目的地へ到着すると降ろす。
- 荷物地点だけの計画(「南の荷物へ行って」)は、積載して終わる。次の指示で目的地へ運ぶと降ろす。

## 迂回の確認手順(確認項目 7)

使う場所は、シミュレータ(noVNC のターミナル)、Mac のターミナル 3 つ(指示 / 診断 / パレット)。

1. 【noVNC】`bash ~/ros2_ws/stop_nav.sh` → `bash ~/ros2_ws/run_nav.sh cargo:=true`
2. 【Mac・指示】`cd ~/Desktop/pai_final/host && source .venv/bin/activate && python llm_commander.py --cargo`
3. 【Mac・診断(任意)】`cd ~/Desktop/pai_final/docker && ./ros_exec.sh python3 /home/ubuntu/ros2_ws/trace_nav.py`(位置・向き・速度指令・計画経路を 1 秒ごとに表示)
4. 【Mac・指示】「南の荷物を出荷口へ運んで」と入力する
5. 【Mac・パレット】`loaded` が出たら、ロボットが x=3.0 に達する前に `cd ~/Desktop/pai_final/docker && ./ros_exec.sh ros2 run ai_nav obstacle place south_aisle`
6. 停止 → `blocked`(南通路)→ 再計画(中央通路経由)→ 出荷口で `unloaded`。撤去は `obstacle remove south_aisle`

診断用: `ros2_ws/check_costmap.py`(各地点のコスト)、`ros2_ws/check_scan.py`(周囲の LiDAR 距離とローカルコストマップ)、`ros2_ws/trace_nav.py`。

## 既知の事項

- 地点名を含まない入力(打ち間違いなど)は、経験として保存しない。保存済みの誤った経験が再計画を乱した例があったため。
- 再計画の案に、目的地に不要な経由地(充電ステーション)が入ると、後退直後に動けなくなる例が 2 回あった。経験の誤保存を除くと再現しなかったが、その後、箱がホール車線をふさいでいたことが主因と分かった。箱の移動後は、南・中央の荷物の搬送が停止なしで完了した。
