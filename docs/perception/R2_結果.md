## 3. 解釈(仮説 M8 の修正)
- 型 C の原因は認識の不足ではなく、通路の特定の規則だった(R0)。規則の修正で型 C は解消した。
- ただし、全体の到着は 53 → 54/60 とほぼ変わらない。型 C を直すと、同じ場面の次の段階の失敗(型 E・B・A)が現れた。
- 修正によって、停止原因の判定が LiDAR のしきい値に強く依存するようになり、余裕 2 点の判定で誤登録が起きた。
  点数のしきい値という規則では、本物の閉塞と、棚・壁の縁の点を分けきれない。**ここが、学習による認識(M8)を使う理由になる。**

## 4. 型 E の原因と修正(2026-10-19)
- 原因は凍結した planner.py ではなく、複数台の検証用クライアント `host/auto_multi.py` の C2 の車線の規則。
  dead・waitj では、計画が南通路を経由地に含まなくても、目的地が南通路側なら南通路の車線(south_lane_e)を最後の目的地の前に足していた。
  南通路を通行止めにした後の迂回案(中央通路経由)にも足したため、通行止めの通路へ戻ろうとした。
- 修正:南通路が通行止めのとき、または計画が中央・北通路を経由するときは、車線を足さない。
  元の測定の再現性を保つため、`EXECUTOR=plan_executor_v2` のときだけ有効にする(`FIX_E`)。
- C2 の修正版の第 1 回(型 E を含む)は `r2_c2_v1/` に移し、C2 だけを測り直す。C0・C3 は車線の規則を使わないため影響しない。
