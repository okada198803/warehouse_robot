## 1. 目的

## 2. 差し替える箇所(他の層に影響させない条件)
- 対象: 立ち往生したときの「原因の分類」(現在は LiDAR の通路帯の点数としきい値による規則)。
- 入力: 停止時の LiDAR スキャン 1 周分と自己位置。出力: `{aisle: 通路 id または none, cls: 物体の種類, conf: 確信度}`。
- 現在の出力(通路 id / 特定できない)は、この出力の一部として保つ。Planner・LLM・検証・Nav2・機体間通信は変更しない。
- 切り替え: パラメータ `recognizer:=rule|learned`。既定は `rule`(凍結した結果をそのまま再現できる)。
- 新しいファイルだけを追加し、凍結ファイル(SHA256_freeze-2026-10-13)は変更しない。作業はブランチ `perception` で行う。

## 4-2. 壁際の停止(型 B)と動作の学習(M9)
**仮説 M9:** 「壁際で動けなくなったときの抜け出し方を学習すれば、固定の回復動作(後退など)より確実に抜け出せる」。
学習が効くのは、原因が「回復動作が単純すぎる」場合に限られる。設定(膨張半径など)の問題なら、調整だけで解決するため、調整を対照条件に入れる。

| ID | 内容 | 指標 | 事前の予想 |
|---|---|---|---|
| R6 | 型 B の 3 件(C1 stag、C3 oppj、C2w)のログを再解析する。局所計画が軌道を出せなかったのか、回復動作が失敗したのかを分ける | 3 件の原因 | 相手を避けて壁側に寄り、膨張半径の内側に入った。回復の後退が同じ位置に戻した |
| R7 | 壁際の停止を再現するシナリオを作る(南通路の西側の壁際に置き、相手で塞ぐ)。元の発生率は約 3/400 で比較できないため、起こりやすくした場面で測る | 規則の条件での脱出率 | 脱出率 50% 前後(比較できる程度に失敗が起きる) |
| R8 | 3 条件を比較(各 20 試行):(a) 現在の回復動作、(b) 設定の調整(膨張半径・回復動作のパラメータ)、(c) 学習した抜け出し方策 | 脱出率、脱出までの時間、接触の有無 | (b) で大半が解決し、(c) は (b) と同等か、(b) で残る場面で上回る |
| R9 | 回帰の確認。単一の迂回と、複数台の opp を (b)・(c) で再実行 | 既存の値からの劣化 | 劣化なし |

**学習の方法:**
- 起動の範囲:立ち往生を検知したときだけ、学習した方策に切り替える(回復動作の置き換え)。通常の走行は Nav2 のまま。
- 入力は LiDAR と自己位置、出力は短時間の速度指令。
- 教師データ:シミュレータの真の位置を使う自動の「手本」(真の位置から壁と相手を避けて抜ける経路を計算して走らせる)で、rosbag2 に記録する。人の遠隔操作(gesture_teleop)は補助に使う。手本の動きを、真の位置を使わずに LiDAR だけで再現できるように学習する(模倣学習)。
- 切り替え:パラメータ `recovery:=default|tuned|learned`。既定は `default`。

**見込みの注意:** 元の失敗は 3 件と少なく、学習が効くかは R6 の原因次第。R6 で設定の問題と分かれば、(c) は行わず (b) の結果だけを記録する。

## 9. R0・R6 の結果(2026-10-19、既存ログ multi/docs/multi/logs/*.jsonl の再解析)
**R0(型 C、6 件):事前の予想は外れた。**
- 6 件とも、最初の停止の時点で残りの目的地が `['shipping']` だけだった。南通路の経由地(中心 x=3.5)を通過済みのため、通路の候補から外れていた。
- `plan_executor.nearest_aisle()` は「まだ到達していない通路(queue 内)」だけを候補にする(通過済みの通路の誤登録を防ぐため)。そのため `near_aisle=None` → `cause=unlocated` となり、LiDAR の点数の確認(`scan_hits`)はそもそも行われていない(全件 `hits=None`)。
- 停止位置は南通路の中か入口付近(x 2.1〜4.7)。停止した相手は、経由地より東側にいた。
- 対照:同じ試行で、まだ南通路の経由地に着いていなかった r2 は `near=south_aisle`、`hits=164` で正しく登録できている。
- **結論:原因は認識(点数不足)ではなく、通路の特定の規則(経由地を通過したら、その通路を候補から外す)。** 停止ロボットの点数は、確認さえすればしきい値を十分に超えうる(r2 の例で 164 点)。

**R6(型 B、3 件):**
- 3 件とも Nav2 が `status 6`(中断)で失敗した。位置は南通路の北壁際(2.4〜2.9, 1.31〜1.44。通路の中心 y=1.05、幅 0.9 m のため壁は y≈1.5)、C2w #5 は西ホール(1.82, 2.1)。
- C1 stag #6 は、壁際で停止 → 通路を特定できず再試行 → 再試行の後に Nav2 が中断。C3 oppj #6・C2w #5 は、立ち往生の報告なしに Nav2 が中断した。
- 実行部は Nav2 の中断を最終的な失敗として扱い、再試行や回復をしない。
- **結論:壁際に寄った後の Nav2 の中断と、中断後に何もしない規則の組み合わせ。** 学習の前に、中断時のコストマップ消去と再試行(規則)、膨張半径の調整を試す余地が大きい。

**計画への影響:**
- M8 は「学習で認識すれば解決」ではなく、まず「通路の特定を、経由地でなく位置(通路の範囲に入っているか)で行い、LiDAR で確認する」規則の修正で検証できる。H5 の誤封鎖の再発は、LiDAR の確認(しきい値 16 点、誤検知 0/432)で防げる見込みで、R3 で確かめる。
- 学習による認識は、型 C の解決には必須でない。物体の種類による行動の選択(人なら待つ、パレットなら迂回)という、発展の問いで価値を測る。
- M9 も、まず規則(中断時の再試行・コストマップ消去)と設定の調整で検証し、残った失敗に対して学習を試す。
